## Overview

**Network anomaly detection** is the task of identifying network traffic that deviates from an established baseline of "normal" behavior. In cybersecurity this is one of the two core detection philosophies used by **Network Intrusion Detection Systems (NIDS)**, the other being signature-based detection (matching known attack patterns). Anomaly-based detection is attractive because it can flag novel or zero-day activity that has no known signature, but it produces more false alarms to tune out.

Modern anomaly detection in practice is usually **machine-learning-based**: a model is trained on labeled (or unlabeled) network data so that, at inference time, each new traffic record is classified as either normal or anomalous/malicious. This is the approach NetGuard AI takes with its Random Forest classifiers.

---

## Definition

- **Anomaly:** An observation that deviates so significantly from expected behavior that it is suspected to be generated by a different process (for example, malicious activity rather than ordinary user traffic).
- **Network anomaly detection:** The automated process of labeling network observations (connection records, flow records, packets, or host behaviors) as normal or anomalous.
- **Intrusion Detection System (IDS):** A system that monitors network or host activity for suspicious behavior. A **NIDS** monitors network traffic specifically.
- **False Positive (FP):** Normal traffic incorrectly flagged as an anomaly. High false-positive rates are the main practical obstacle to anomaly-based IDS deployment.
- **False Negative (FN):** Anomalous/malicious traffic incorrectly labeled normal, which could allow an attack to proceed undetected.

**Alternative / related terminology:** outlier detection, deviation detection, behavioral detection, NIDS machine-learning classification.

## Key Concepts

### Types of Anomalies
- **Point anomalies:** A single observation is abnormal in isolation (e.g., one flow record consuming an implausible amount of bandwidth relative to the baseline).
- **Contextual anomalies:** An observation is abnormal only within a particular context (e.g., a large inbound burst during off-peak hours may be suspicious, while the same burst during a scheduled backup window is expected).
- **Collective anomalies:** A sequence of otherwise-normal observations is abnormal as a group (e.g., a coordinated low-and-slow pattern across many hosts, each individually unremarkable).

### Supervised vs. Unsupervised Approaches
- **Supervised:** A model is trained on labeled data where each record is known to be normal or a specific attack. NetGuard AI's Random Forest classifiers on NSL-KDD and CICIDS-2017 are supervised.
- **Unsupervised / statistical:** Deviations are detected against learned baselines without labels (e.g., clustering or per-feature statistics such as mean and standard deviation; an observation far from the baseline is flagged). These methods cope with zero-day attacks but are typically noisier.

### Why Benchmarks Matter
Anomaly detectors are only as good as the data they are validated on. Public benchmark datasets (NSL-KDD, CICIDS-2017) provide labeled traffic so that detection accuracy can be measured reproducibly with metrics such as accuracy, precision, recall, F1-score, and ROC-AUC. See the NSL-KDD and CICIDS-2017 guides in this knowledge base for dataset-level detail.

## Technical Details

### Statistical Detection Basics
Simple statistical anomaly detection builds per-feature baselines from historical traffic and flags records whose features deviate by more than a chosen threshold (for example, several standard deviations from the mean). This is fast and interpretable but struggles with correlated, multivariable traffic patterns.

### Machine-Learning Detection
Supervised ML detection treats the problem as a classification task:
1. Each network record is converted into a fixed-length feature vector (NSL-KDD: 41 connection record features; CICIDS-2017: roughly 78-80 per-flow statistical features).
2. Categorical features are encoded numerically (label/one-hot encoding).
3. A classifier (in NetGuard AI, a Random Forest) is trained to separate normal records from malicious ones.
4. At inference, each new record yields a predicted class and, if available, a class probability used as a confidence score.

### Random Forest Suitability
Random Forest is a good fit for this problem because it handles many numeric and categorical features, is robust against overfitting on noisy traffic data, supports feature-importance analysis (which features most influence the decision), produces fast predictions, and offers high accuracy on the benchmark datasets.

### Anomaly Severity and Confidence
In production-style systems the raw label is usually enriched with a **severity** and a **confidence** value so that alerts can be prioritized. Confidence typically derives from the model's predicted class probability; severity combines how dangerous the detected attack family is with how confident the model is. See the `severity_and_confidence` document in the Datasets & Machine Learning section of this knowledge base.

## How NetGuard AI Uses It

NetGuard AI is a **machine-learning NIDS** that:
- Trains two **Random Forest** classifiers, one on **NSL-KDD** (41-feature connection records) and one on **CICIDS-2017** (78-80 flow features), producing `nsl-kdd_anomaly_model.pkl` and `cicids_anomaly_model.pkl` together with their label encoders.
- Exposes prediction through a **FastAPI backend** so sampled network captures can be classified as normal or malicious with severity and confidence.
- Explains predictions through a **RAG-grounded chat assistant**, which retrieves the relevant knowledge-base documents (this one included) and answers using only retrieved evidence.

Reported benchmark results in the project README: NSL-KDD test accuracy 99.91%, CICIDS-2017 test accuracy 99.85% (training accuracy 99.97% and 99.99% respectively). These are single-run training results of the project, not generalized production claims.
